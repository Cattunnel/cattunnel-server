# Расхождения с upstream TrustTunnel (endpoint, выпуск 1.5.9.5)

Английский перевод: [upstream-divergence.en.md](upstream-divergence.en.md); при расхождении верен русский текст.

Документ перечисляет, чем endpoint CatTunnel (этот репозиторий) отличается от
upstream TrustTunnel в выпуске 1.5.9.5. Описано текущее состояние, не история.

Сравниваемые версии. Merge-base форка с upstream это `v1.3.0-beta.2` (`48f424c`).
Содержимое upstream `v1.3.1` (TRUST-773, TRUST-805, TRUST-826) включено, поэтому
сравнение ниже идёт с `v1.3.1`. Измерено `git diff --numstat v1.3.1 HEAD`: 45
файлов, 13351 вставка, 240 удалений. Измерено
`git merge-tree --write-tree --name-only HEAD v1.3.1`: конфликты только в
`CHANGELOG.md` и `lib/tests/subscription.rs`.

Классы: А, форк добавил то, чего нет в upstream; Б, upstream делает иначе и код форка
с этим несовместим или мешает слиянию; В, та же задача решена по-другому. У ядра клиента
свой список в его репозитории.

```text
 TCP :443 ----------------------+        TCP :cattail port
                                 |                |
                                 |        [A1 CatTail admission,
                                 |         silence, frames]
                                 v                v
                        +---------------------------------+
                        | TlsListener                     |
                        |  [A6 join split ClientHello,    |
                        |      count JA4]                 |
                        +----------------+----------------+
                                         v
                        +---------------------------------+
                        | TlsDemux: SNI + ALPN            |
                        |  [B1 h2 on decoy hosts]         |
                        +----------------+----------------+
                                         v
                        +---------------------------------+
                        | HttpDemux: per request          |
                        |  [A2 NineLives channel]         |
                        +-----+-----------+----------+----+
                              v           v          v
                          tunnel      decoy site   subscription
                          [A5 decoy-  [A7 h1 keep-  (upstream)
                           only check] alive, bodies]
                          [A3 200 headers]
                          [A4 DATA 4096]
```

## А. Отошли: добавлено форком, в upstream этого нет

### A1. Внешний слой CatTail

- Upstream: Внешнего слоя нет: каждое соединение начинается с TLS ClientHello на листенере.
- Форк: Второй TCP-листенер, настраиваемый `[cattail]` (`lib/src/settings.rs:94`), запускается вместе с остальными (`lib/src/core.rs:215`). Допуск, молчание и кадрирование в `lib/src/cattail.rs:1052`; внутренние байты идут в `Core::serve_stream`.
- Зачем: На проводе нет заголовков TLS-записей, SNI и фиксированного префикса, а зонд получает молчание вместо веб-сайта.
- Совместимость: Свой порт, выключен, пока нет `[cattail]`. Официальные клиенты его использовать не могут; путь официального клиента (порт 443) не меняется. Спецификация: [cattail.md](cattail.md).

### A2. Транспорт NineLives (XHTTP)

- Upstream: Единственный способ туннелировать TCP это CONNECT; транспорта сессий на GET/POST нет.
- Форк: Канал маршрутизации `lib/src/http_demultiplexer.rs:63` и обработчик `lib/src/http_xhttp.rs:1058`; набор шифрования 1 в `lib/src/xhttp_crypto.rs:48`; настройки `xhttp_*` (`lib/src/settings.rs:275`).
- Зачем: Сессия переживает смерть одного TLS-соединения (возобновление) и имеет собственное шифрование тела.
- Совместимость: По умолчанию `xhttp_enable = false`. Несовместим с XHTTP из Xray и с официальными клиентами. См. [ninelives.md](ninelives.md).

### A3. Правдоподобный ответ 200 на CONNECT

- Upstream: Пустой `200` (`upstream v1.3.0-beta.2:lib/src/http_downstream.rs:226`).
- Форк: `date`, `server: nginx`, `cache-control`, два hex-идентификатора случайной длины (`lib/src/http_codec.rs:38`, вызов в `lib/src/http_downstream.rs:256`).
- Зачем: Пустой ответ одного размера каждый раз выдаёт туннель; заголовки идут внутри TLS и видны только размером.
- Совместимость: Обычные заголовки HTTP/2, контракт не меняется. С официальным клиентом в этом репозитории не проверялось.

### A4. Кадры DATA по 4096 байт на CONNECT

- Upstream: Каждая запись заполняет окно: `to_send = self.tx.capacity()` (`upstream v1.3.0-beta.2:lib/src/http2_codec.rs:338`).
- Форк: Для потоков CONNECT `capacity().min(4096)` (`lib/src/http2_codec.rs:352`); остальные методы сохраняют полное окно.
- Зачем: Размер кадров DATA от сервера входит в форму трафика; форк использует размер кадра, как у браузера (так назван тест в `http2_codec.rs`).
- Совместимость: Любой h2-клиент принимает меньшие кадры.

### A5. decoy_only_ips_file

- Upstream: Списка нет: адрес получает отказ только за неверные учётные данные.
- Форк: `DecoyList`, перечитывается по времени изменения (`lib/src/decoy_list.rs:19`); проверяется для CONNECT (`lib/src/http_downstream.rs:130`), NineLives, подписки, учётных данных в SNI и CatTail.
- Зачем: Адрес, пробовавший закрытый порт, может видеть сайт, но не VPN, даже с верными учётными данными.
- Совместимость: Легитимный клиент из списка получит отказ; список наполняет файрвол хоста.

### A6. Склейка разрезанного ClientHello, счёт JA4

- Upstream: Разбирается одна TLS-запись (`upstream v1.3.0-beta.2:lib/src/tls_listener.rs:72`).
- Форк: Фрагменты рукопожатия склеиваются, пока сообщение не станет целым (`lib/src/tls_listener.rs:81`); строка JA4 учитывается (`lib/src/tls_listener.rs:133`) и отдаётся по `lib/src/metrics.rs:19`.
- Зачем: RFC 8446, раздел 5.1, позволяет клиенту разрезать ClientHello по записям, и комментарий в коде называет anti-DPI CatTunnel источником; счётчик JA4 показывает, какие отпечатки клиентов доходят до endpoint'а.
- Совместимость: Надмножество разбора upstream; обычный ClientHello в одной записи работает как раньше.

### A7. Сайт-заглушка ведёт себя как настоящий сайт

- Upstream: HTTP/1.1-соединение закрывается после первого ответа (`upstream v1.3.1:lib/src/http1_codec.rs:233`); тело запроса к заглушке отправляется после прихода ответа.
- Форк: Соединение обслуживает следующий запрос (`lib/src/http1_codec.rs:204`); тело запроса пересылается, пока ждут ответ (`lib/src/reverse_proxy.rs:662`); строки размера чанка и трейлеры ограничены (`lib/src/http_forwarded_stream.rs:16`); на хостах-заглушках разрешён h2 (B1).
- Зачем: Браузер, открывающий страницу, должен получить то же поведение, что у обычного веб-сервера, иначе заглушка выдаёт себя.
- Совместимость: Затрагивает только путь заглушки. Файлы `http_forwarded_stream.rs` и `reverse_proxy.rs` сильно переписаны (см. B2).

## Б. Конфликтуем: upstream делает иначе, либо слияние требует решения

### B1. h2 на хостах-заглушках (обратный прокси)

- Upstream: ALPN `h2` на хосте обратного прокси отклоняется: проходят только `Http1 | Http3` (`upstream v1.3.1:lib/src/tls_demultiplexer.rs:286`), а тест ожидает ошибку для `h2` (`upstream v1.3.1:lib/src/tls_demultiplexer.rs:571`).
- Форк: Принимаются `Http1 | Http2 | Http3`, выбирается высший из предложенных клиентом (`lib/src/tls_demultiplexer.rs:286`); тест переписан и ожидает `Http2`.
- Зачем: Клиент в форме браузера предлагает `h2`; сайт, который его отвергает, не похож на обычный.
- Совместимость: Настоящий конфликт по смыслу: слияние тестов upstream упадёт, пока этот тест не оставлен нашим. Официальные клиенты на туннельных хостах не затронуты.

### B2. Сильно изменённые файлы upstream

- Upstream: Файлы как в `v1.3.1`.
- Форк: Относительно `v1.3.1` форк меняет 15 существующих файлов и добавляет 30 новых (`git diff --numstat v1.3.1 HEAD`: 45 файлов, +13351, -240). Крупнейшие правки существующих файлов: `http_forwarded_stream.rs` (+441/-44), `reverse_proxy.rs` (+345/-31), `tls_listener.rs` (+166/-41), `http1_codec.rs` (+153/-14), `core.rs` (+85/-39), `http2_codec.rs` (+101/-3). Точки входа: `lib/src/core.rs:364`, `lib/src/http_downstream.rs:179`.
- Зачем: Правки заглушки и новый листенер требуют крючков внутри кода upstream.
- Совместимость: `v1.3.1` эти файлы не трогает, поэтому пробное слияние в `lib/src` чистое. Будущие правки upstream в обратном прокси или TLS-листенере будут конфликтовать.

### B3. Одно изменение перенесено дважды (CHANGELOG, тесты подписки)

- Upstream: TRUST-773 `Content-Length: 0` с тестами в `lib/tests/subscription.rs` и строкой CHANGELOG (коммит upstream `3826388`).
- Форк: То же изменение кода в `lib/src/http_codec.rs:191` плюс собственные тесты для ответов CONNECT и decoy-only (`lib/tests/authentication.rs:445`).
- Зачем: Изменение взято, когда `v1.3.1` был кандидатом; тесты расширены, поэтому файлы различаются.
- Совместимость: `git merge-tree HEAD v1.3.1` показывает конфликты только в `CHANGELOG.md` и `lib/tests/subscription.rs`; код сливается чисто.

### B4. Теги deep link

- Upstream: Формат `tt://` определяет теги от `0x00` до `0x10`, где `0x10` числовой `tls_profile` (TRUST-826) (`deeplink/src/types.rs:25`).
- Форк: Крейт upstream, по смыслу без изменений. Параметры NineLives и CatTail этим крейтом не переносятся; их несёт подписка вне этого репозитория.
- Зачем: Перечисление TLS-профилей в клиенте расходится с числами тега `0x10` (см. документ клиента).
- Совместимость: Разборщики игнорируют неизвестные теги, поэтому лишние теги официальные клиенты не ломают. Будущий тег upstream может занять номер, который подписка уже использует.

## В. Та же задача решена по-другому

### C1. Зондирование endpoint'а

- Upstream: Каждое соединение получает TLS-рукопожатие и без верных учётных данных сайт-заглушку или ошибку аутентификации (`lib/src/http_downstream.rs:144`).
- Форк: Сохраняет это, добавляет список decoy-only (A5) и на порту CatTail молчание: ни одного байта не пишется, соединение заканчивается в случайный момент (`lib/src/cattail.rs:63`).
- Зачем: Ответ сайта доказывает, что кто-то слушает; молчание на порту без службы похоже на закрытый порт.
- Совместимость: Подходы друг друга не затрагивают: порт 443 ведёт себя как upstream плюс список decoy-only.

### C2. Поддержание простаивающего туннеля

- Upstream: У endpoint'а есть authority проверки `_check`, и он ждёт запросы не дольше `client_listener_timeout` (`lib/src/http_downstream.rs:21`, `upstream v1.3.0-beta.2:lib/src/settings.rs:106`).
- Форк: Сервер не менялся. Клиент шлёт `_check` через случайные интервалы как keepalive, потому что HTTP/2 PING запросом не является (`lib/src/tunnel.rs:131`).
- Зачем: Использует механизм upstream вместо нового серверного.
- Совместимость: Работает с немодифицированным endpoint'ом upstream.

## Взято из upstream, расхождения нет

- TRUST-773, `Content-Length: 0` на ответах с ошибкой: то же изменение кода, что в
  upstream (`lib/src/http_codec.rs:191`).
- TRUST-826, `tls_profile` как тег `0x10` deep link: крейт upstream.
- TRUST-805, мастер настройки в основных бинарниках: изменение upstream.
- Проверки префикса `client_random` и ключа аутентификации в TLS-листенере: upstream
  (`lib/src/client_random_prefix.rs:5`).

## Не в 1.5.9.5

Запланировано на 1.5.9.10 и здесь отсутствует: полный переход ядра клиента на upstream
`v1.3.0` и обратный выход.
